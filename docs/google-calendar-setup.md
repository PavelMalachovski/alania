# Настройка Google Calendar (для Ланы)

Бот сам смотрит в твой календарь и предлагает клиентам только реально
свободное время, а после оплаты ставит консультацию в отдельный календарь
«Консультации». Ниже — как один раз всё настроить.

○─── ☾ ───○

## 1. Google Cloud Console → новый проект → включить Calendar API

1. Открой [console.cloud.google.com](https://console.cloud.google.com/) и
   войди под тем же Google-аккаунтом, где твой основной календарь.
2. Создай новый проект (например, `alania-bot`).
3. В меню слева: **APIs & Services → Library**, найди «Google Calendar API»
   и нажми **Enable**.

## 2. Создать сервис-аккаунт и JSON-ключ

1. **APIs & Services → Credentials → Create Credentials → Service account**.
2. Дай ему любое имя (например, `alania-booking-bot`), роль можно не
   назначать — доступ к календарям выдаётся отдельно, шагом ниже.
3. Открой созданный сервис-аккаунт → вкладка **Keys → Add Key → Create new
   key → JSON**. Файл скачается на компьютер — это и есть
   `GOOGLE_SA_CREDENTIALS`. Держи его в секрете, как пароль.
4. Внутри JSON есть поле `client_email` — что-то вроде
   `alania-booking-bot@alania-bot.iam.gserviceaccount.com`. Он понадобится
   на следующих шагах.

## 3. Создать календарь «Консультации»

1. Открой [calendar.google.com](https://calendar.google.com/), в разделе
   «Другие календари» нажми **+ → Создать новый календарь**.
2. Назови его «Консультации» — именно в него бот будет ставить
   подтверждённые записи после оплаты.

## 4. Расшарить «Консультации» сервис-аккаунту

1. Наведи на календарь «Консультации» → три точки → **Настройки и
   доступ**.
2. В разделе «Доступ для отдельных пользователей» добавь email
   сервис-аккаунта (`client_email` из шага 2) с правом
   **«Вносить изменения в мероприятия»** — боту нужно и создавать, и
   удалять события (если Лана отклоняет оплату — событие удаляется).

## 5. Расшарить личный (основной) календарь сервис-аккаунту

Это тот календарь, где у тебя уже есть личные встречи, дела и т.п. — бот
должен видеть его занятость, чтобы не предлагать клиентам время, когда ты
занята чем-то своим.

1. Так же: настройки календаря → «Доступ для отдельных пользователей» →
   добавить email сервис-аккаунта.
2. Права — достаточно **«Просматривать все данные о мероприятиях»** (бот
   только читает занятость через freebusy, ничего не меняет в личном
   календаре).

## 6. Скопировать Calendar ID обоих календарей

1. Для каждого календаря: настройки → раздел **«Интеграция календаря»** →
   поле **«Идентификатор календаря»**.
2. Для «Консультации» это обычно строка вида
   `xxxxxxxxxxxx@group.calendar.google.com`.
3. Для личного календаря — либо твой email (если это основной календарь
   аккаунта), либо такая же длинная строка, если это дополнительный
   календарь.

## 7. Заполнить переменные окружения

В `.env` (или в переменных окружения на Railway) заполни:

```
GOOGLE_SA_CREDENTIALS=<путь до скачанного JSON-файла ИЛИ его содержимое целиком>
CALENDAR_ID_BOOKINGS=<Calendar ID календаря «Консультации» из шага 6>
CALENDAR_ID_PERSONAL=<Calendar ID личного календаря из шага 6>
```

`GOOGLE_SA_CREDENTIALS` можно задать двумя способами — бот сам определяет,
что перед ним, по первому символу значения:
- **путь к файлу** — например, `/app/service-account.json` (удобно локально);
- **содержимое JSON целиком** одной строкой — удобно для Railway, где нет
  файловой системы для секретов: просто вставь весь JSON как значение
  переменной.

После этого остальные настройки записи (расписание, длительность холда,
горизонт брони) — см. README, раздел «Переменные окружения».

## Важно: если БД уже использовалась (миграций нет)

Таблица `bookings` под запись через Google Calendar имеет другую схему, чем
раньше (`slot_start`/`held_until`/`google_event_id` вместо старых
`slot_date`/`slot_time`). Миграций в проекте нет — `create_all` при старте
только **создаёт отсутствующие** таблицы, но никогда не меняет схему уже
существующей. Если на этой базе таблица `bookings` уже была создана старой
версией бота, новый код с ней не заработает.

Один раз перед первым запуском новой версии на такой базе выполни:

```sql
DROP TABLE IF EXISTS bookings;
```

Данные там тестовые (бот ещё не в проде) — их не жалко. После этого
`create_all` создаст таблицу заново в правильной схеме. На свежей базе, где
`bookings` ещё не было, ничего делать не нужно.

## Проверка, что всё работает

1. Запусти бота, нажми «Записаться» — должны появиться дни с реальными
   свободными слотами (не занятые в обоих календарях).
2. Поставь в личном календаре тестовую встречу на один из предлагаемых
   слотов — обнови экран записи (или зайди заново), слот должен пропасть.
3. Дойди до оплаты и нажми «✓ Я оплатил(а)» на тестовой заявке — в
   календаре «Консультации» должно появиться событие «Консультация — Имя».
   Отклони оплату через кнопку у админа — событие должно удалиться.

Если бот пишет «Расписание сейчас недоступно» — значит не настроен доступ
(проверь шаги 4–5) или неверны `CALENDAR_ID_*` / `GOOGLE_SA_CREDENTIALS`.
