Дата: 2026-07-26

## Цель

Три пласта работы над Telegram-ботом Ланы:

1. **Структура меню** — добавить пункт «Пройти тест», убрать раздел «Менторство».
2. **Тексты** — сдвиг тона: убрать «ченнелинг / энергии / тело-подсознание», перейти на
   «интегративный подход: психология, коучинг, духовность». Обновить факты по консультации.
3. **Новая фича** — интерактивный тест «Кто управляет твоей жизнью?» (15 вопросов, баллы 1–4,
   3 итоговых уровня).

## Решения (зафиксированы с заказчиком)

| Тема | Решение |
|---|---|
| Менторство | Убрать полностью: кнопка, `MENTORING_TEXT`, `cb_mentoring`, `mentoring_kb` |
| Тон текстов | Заменить «ченнелинг/энергии» на «интегративный подход» **везде, включая отзывы** |
| Результат теста | Только показать пользователю. В БД не пишем, админам не уведомляем |
| Порядок вариантов | Фиксированный «вразнобой» (одинаков для всех), не по возрастанию баллов |
| Формат ответов | Каждый вариант — отдельная длинная кнопка с полным текстом |
| Схема теста | FSM, одно редактируемое сообщение, кнопка «Назад» с перевыбором, без БД |
| Цена/длительность консультации | 70 минут, 100 € / 10000 ₽, обе кнопки оплаты остаются |
| Стиль теста | Минимализм как весь бот: символы вместо цветных эмодзи (🔴🟡🟢 → ◯ ◐ ●) |

### Открытый пункт на стороне заказчика
Кнопки оплаты ведут на внешние ссылки Tribute с зашитой суммой (`PAY_RUB_URL`, `PAY_EUR_URL`).

Из бота эти суммы не управляются.

### FSM теста
```
class Quiz(StatesGroup):
    in_progress = State()
```
Состояние хранит:
- `answers: dict[int, int]` — {индекс вопроса: выбранный балл}. Позволяет «Назад» и перевыбор.
- `idx: int` — текущий индекс вопроса (0..14).

Итоговый балл = `sum(answers.values())` после 15-го ответа.

### Callback-контракт теста
| callback_data | Действие |
|---|---|
| `quiz_intro` | Открыть экран-интро (из главного меню) |
| `quiz_begin` | Старт/рестарт: `answers={}`, `idx=0`, показать вопрос 0, войти в `Quiz.in_progress` |
| `quiz_ans:<score>` | Записать `answers[idx]=score`; если `idx<14` → `idx+=1`, показать вопрос; иначе показать результат, `state.clear()` |
| `quiz_back` | `idx-=1`, показать вопрос `idx` (с ранее выбранным ответом); на первом вопросе кнопки нет |

Все `quiz_ans:*` и `quiz_back` — под `StateFilter(Quiz.in_progress)`.
`quiz_intro`/`quiz_begin` — без фильтра состояния (вход и рестарт с экрана результата).

### Клавиатуры теста (`keyboards/inline.py`)
- `quiz_intro_kb()` → `[Начать тест (quiz_begin)]`, `[⇦ В меню (start_menu)]`
- `quiz_question_kb(options, is_first)` → 4 кнопки `quiz_ans:<score>` (полный текст варианта),
  затем `[⇦ Назад (quiz_back)]` если `not is_first`, затем `[✕ Прервать (start_menu)]`. `adjust(1)`.
- `quiz_result_kb()` → `[Написать в ЛС (url=DM_URL)]`, `[Пройти заново (quiz_begin)]`, `[⇦ В меню (start_menu)]`

## Обработка ошибок и краевые случаи
- `quiz_ans:*` / `quiz_back` вне состояния `Quiz.in_progress` — игнор (StateFilter отсекает).
- «Назад» на первом вопросе — кнопки нет (`is_first`), некуда возвращаться.
- Повторный вход `quiz_begin` с экрана результата — сбрасывает `answers` и стартует заново.
- `CallbackSafetyMiddleware` гасит `TelegramBadRequest: message is not modified` — отдельно не ловим.
- Балл в `quiz_ans:<score>` валидируется диапазоном 1–4 перед записью.

## Проверка
- `python -m py_compile main.py database.py middlewares.py filters.py followup.py handlers/*.py keyboards/inline.py quiz_data.py`
