# Лендинг v5 — перенос нового дизайна из bundled-экспорта

Лана прислала новый сайт одним файлом: `Lana Leonovich - сайт.html`, 16,8 МБ,
self-contained бандл. Внутри — готовая страница, ассеты в base64 и React-рантайм,
который её оживляет. Задача: положить эту страницу в `web/` так, чтобы она
дальше жила и правилась как остальной статический сайт.

Решение: **полная замена** `web/index.html`. Предыдущая версия (палитра
фарфор/тёмно-синий, Inter, спека `2026-08-03-landing-v2-design.md`) уходит
в историю git.

## Что внутри бандла

| Часть | Содержимое |
|---|---|
| Разметка | 62 КБ готового HTML — секции `top`, `requests`, `method`, `reviews`, `services`, `faq` |
| Стили | 5 блоков `<style>`, ~8 КБ, плюс инлайновые `style=` на элементах |
| Шрифты | 8 woff2: Golos Text (4 сабсета) и Prata (4 сабсета), ~147 КБ |
| JS | react + react-dom + `dc-runtime` + дизайн-система `LanaLeonovichDesignSystem` ≈ 276 КБ |
| Фото | один JPEG 3304×4130, **11,8 МБ**, прямо из Photoshop |

Ключевое наблюдение: **вся разметка и все тексты уже статические**. React
нужен ровно для одного — аккордеона FAQ (6 вопросов, 18 плейсхолдеров
`{{ t0..t5 }}`, `{{ m0..m5 }}`, `{{ d0..d5 }}` и атрибуты `sc-camel-on-click`).
Значит 276 КБ JS выкидываются без потери контента.

## Подход

Распаковываем бандл в обычную статику — так же, как устроен `web/` сейчас:
один HTML, ассеты рядом, никакой сборки, Vercel раздаёт как есть.

Отвергнутые варианты:

- **Положить бандл как есть.** Ноль работы, но 16,8 МБ в git, 11,8 МБ фото
  каждому посетителю и страница, в которой нельзя поправить ни строчки.
- **Распаковать, но оставить React.** Поведение 1:1 ценой 276 КБ JS ради
  аккордеона и чужой дизайн-системы неизвестного происхождения в репозитории.

## Структура файлов

```
web/
  index.html          новый лендинг: разметка бандла + один <style> + FAQ на <details>
  assets/
    lana.webp         новое фото, 1600×2000, цель ~110 КБ
    lana.jpg          jpg-фолбэк, ~310 КБ
    og.jpg            новый кадр 1200×630 для превью ссылки
    favicon.svg       монограмма ЛЛ терракотой — закрывает известный 404
    fonts/            8 woff2 из бандла
  legal/              УДАЛЯЕТСЯ целиком
  vercel.json         + кеш-заголовки для assets/fonts/
  README.md           переписывается под новую страницу
```

## Что переносится дословно, а что переписывается

**Дословно:** вся разметка секций, все тексты, 5 блоков CSS (склеиваются в один
`<style>` в `<head>`), инлайновые `style=` остаются как есть. Картинка не должна
поехать — переносим байты, а не пересобираем вёрстку.

**Переписывается — аккордеон FAQ и блок отзывов.** Шесть карточек вида

```html
<div sc-camel-on-click="{{ t0 }}">…<span>{{ m0 }}</span></div>
```

становятся `<details>` / `<summary>`; знак `+`/`−` рисуется CSS-псевдоэлементом
и поворачивается по `[open]`. Все 18 плейсхолдеров обязаны исчезнуть — иначе
`{{ m0 }}` покажется в тексте страницы буквально.

**Выкидывается:** обёртки `<x-dc>` и `<helmet>`, оба `<script src="…">`,
react, react-dom, `dc-runtime`, дизайн-система. JS на странице не остаётся
вообще.

## Отзывы листаются вбок

Отдельное требование, пришедшее после утверждения дизайна: семь отзывов
должны листаться свайпом. Сейчас они выложены CSS-мульти-колонкой
(`columns:2` на десктопе, `columns:1` на мобильном) — заменяем на
горизонтальную ленту **одинаково на всех ширинах**.

Делается нативным `scroll-snap`, без JS: контейнер получает
`display:flex` + `overflow-x:auto` + `scroll-snap-type:x mandatory`,
карточки — `scroll-snap-align:start` и фиксированную ширину
`min(420px, 82vw)`, чтобы следующая выглядывала за краем и лента читалась
как листаемая.

Два обязательных условия. `overscroll-behavior-x:contain` — иначе свайп
до конца ленты на iOS уводит браузер назад по истории. И `tabindex="0"`
на контейнере — прокручиваемая область должна быть достижима с клавиатуры.

Побочный эффект принят: десктопный вид отзывов перестаёт совпадать с тем,
что утверждала Лана, — вместо двух колонок появляется лента.

## Палитра и типографика

Из бандла, менять не нужно — фиксируем, чтобы правки не разъезжались:

| Токен | Значение | Роль |
|---|---|---|
| `#C8705A` | терракота | акцент, ссылки, метки разделов |
| `#1C1C2E` | почти чёрный | заголовки и основной текст |
| `#6B6560` | тёплый серый | вторичный текст |
| `#2B3366` | глубокий синий | тёмные блоки |
| `#E8DDD4` | бежевый | границы и карточки |
| `#F5EDE3` | песочный | подложки |
| `#FAFAF7` | почти белый | фон страницы |
| `#E0A48F` | светлая терракота | акцент на тёмном |

Шрифты: **Golos Text** (400/500/600) — основной, **Prata** — заголовки.
Размеры и ритм заданы кастомными свойствами (`--fs-*`, `--lh-*`, `--rhythm`,
`--wrap` и др.) в первом блоке CSS; они переносятся как есть.

## Шрифты раздаём сами, не с Google CDN

8 файлов кладутся в `assets/fonts/`, `@font-face` объявляются с сабсетами по
`unicode-range` ровно как в оригинале, `font-display: swap`, `preload` на два
кириллических сабсета. Файлов именно 8, а не 16: у Golos Text один и тот же
файл объявлен на веса 400, 500 и 600 — так его отдаёт Google Fonts, и мы
повторяем это один в один.

Причина не в скорости. П. 12.1 Политики конфиденциальности утверждает, что
сайт статический, cookie не ставит, аналитики и сбора данных нет. Google Fonts
с CDN отдаёт Google IP-адрес каждого посетителя — формулировка перестала бы
быть правдой. Своя раздача снимает вопрос.

## Фото

Новое, и это другой кадр: лесной портрет в белом вместо тёплого кадра
у зеркала. Обработка — по рецепту из `web/README.md`:

- `lana.webp` и `lana.jpg`, 1600×2000, цель ~110 КБ и ~310 КБ;
- в разметке `<picture>`: webp с jpg-фолбэком;
- атрибуты `width`/`height` у `<img>` обязательно вместе с `height: auto`
  в CSS — без этого презентационная подсказка перебивает `aspect-ratio`
  и картинка растягивается;
- `og.jpg` 1200×630 пересобирается из того же исходника: старый — кадр
  прежней фотосессии и к новой странице не подходит;
- исходник 11,8 МБ в репозиторий не кладём.

## Деплой и кеш

Vercel без изменений: Root Directory `web`, Framework Preset Other, команда
сборки пустая. В `vercel.json` добавляется правило для `assets/fonts/*` —
сутки с `stale-while-revalidate`, как у фото. `immutable` не ставим по той же
причине, что и там: имена файлов не содержат хеша, и замена шрифта не доехала
бы до тех, кто уже был на странице.

## Проверка

```bash
python -m http.server 4321 --directory web
```

Прогоняем страницу в браузере и убеждаемся:

- консоль без ошибок, сеть без 404 (особенно шрифты и фото);
- `{{ … }}` нигде не видно в тексте;
- аккордеон FAQ открывается и закрывается, все шесть вопросов;
- якорная навигация ведёт в свои секции;
- вид на десктопе и на мобильном, страница не скроллится вбок;
- все внешние ссылки открываются, юр-ссылки ведут в нужные документы.

Автотестов у сайта нет и не заводим: статическая страница без логики.

## Что не трогаем

- Бота — кроме уже висящего PR #26, эта работа его не касается.
- `?start=site` бот по-прежнему не разбирает: `handlers/start.py` не читает
  `command.args`, человек попадёт на главный экран вместо раздела. Расхождение
  старое, переносится как есть, чинится отдельной задачей.
- Дизайн-систему и сборку из бандла не тащим.
