# alania

Telegram-бот воронки продаж для эксперта: прогрев аудитории, презентация услуг,
запись на консультацию по слотам, приём заявок, выдача бесплатного
гайда-лид-магнита, рассылки и дожим-напоминания.

## Возможности

- **Главное меню** — навигация по услугам и материалам (inline-кнопки),
  открывается кнопкой «🏠 Меню» на нижней клавиатуре.
- **Нижняя клавиатура** — после `/start` под полем ввода закрепляются 4
  быстрые кнопки: «📅 Записаться», «📋 Мои записи», «🏠 Меню» и «💬 Вопрос
  Лане» (сразу ссылка написать в ЛС). Работают вне активных диалогов —
  пока пользователь заполняет форму (например, вводит причину переноса),
  бот не путает текст кнопки с ответом на вопрос.
- **Уборка сообщений** — бот старается не оставлять в чате лишнюю
  переписку: поток «причина переноса» (перенос записи меньше чем за 24
  часа) схлопывается в одно редактируемое сообщение, а текст, который
  вводит клиент, сразу удаляется; уведомления, которые получает Лана после
  нажатия «Подтвердить»/«Отклонить» (оплата или перенос), сворачиваются в
  короткую итоговую строку вместо развёрнутой карточки.
- **Личная работа** — консультация «Точка сборки»: описание, «кому подойдёт»,
  как проходит сессия, отзывы с пагинацией.
- **Запись по слотам из Google Calendar** — бот сам считает свободное время
  (будни, `WORK_TIMES`) по занятости двух календарей Ланы (рабочего и
  личного), занятые и прошедшие слоты не показываются. Выбранный слот
  держится за клиентом `BOOKING_HOLD_MINUTES` (по умолчанию 30 минут), пока
  идёт оплата.
- **Оплата через lava.top с автоподтверждением** — клиент выбирает рубли
  или евро (`50 € / 5000 ₽`), один раз вводит email (на него lava.top
  шлёт чек; бот запоминает адрес), бот выставляет персональный счёт и даёт
  ссылку на оплату. Статус счёта бот проверяет сам (фоновая задача, плюс
  кнопка «✓ Я оплатил(а)» для мгновенной проверки): как только оплата
  прошла — запись подтверждается, в календаре «Консультации» создаётся
  событие, клиенту «Вы оплатили, спасибо…», Лане — уведомление. Если
  клиент заплатил после истечения брони, а слот успели занять, запись
  уходит Лане на ручное решение (другое время или возврат). Криптовалюты
  больше нет. Перед счётом — отдельные кнопки-подтверждения по оферте:
  согласие на обработку сведений о состоянии (один раз) и просьба начать
  до истечения 14 дней (перед каждым заказом); бот хранит время каждого.
- **Лимит активных записей** — не больше 5 одновременных записей (held +
  confirmed в будущем) на одного клиента — дальше бот просит сначала
  завершить или перенести одну из существующих.
- **«Мои записи» и перенос** — кнопка в главном меню показывает будущие
  оплаченные/подтверждённые записи клиента, у каждой — «Перенести» → выбор
  нового дня и времени из тех же свободных слотов. Если до исходной сессии
  ещё ≥24 часов, перенос применяется сразу. Если осталось <24 часов, бот
  просит указать причину и отправляет запрос Лане (кнопки «✅ Подтвердить
  перенос» / «❌ Отклонить перенос»); отклонение переноса **отменяет
  запись** (оплата не возвращается), подтверждение — двигает слот (с
  повторной проверкой, что он всё ещё свободен).
- **Заявка** — пошаговая анкета (имя → запрос → контакт), сохраняется в БД,
  всем админам приходит уведомление с профилем клиента.
- **Дожим** — если человек интересовался консультацией, но за час не записался,
  бот один раз присылает «могу ли чем-то помочь?».
- **Гайд-лид-магнит** — «Карта твоего запроса» отдаётся файлом прямо из бота.
- **Рассылки** — любой контент: текст, фото, видео, голосовые.
- **Игра VECHNOST** — описание, оплата через lava.top (рубли/евро) и
  ссылка на бот игры. **Бесплатный Telegram-канал** — ссылка-переход.
- **Курс-практикум «Взломай Реальность»** — описание и оплата через
  lava.top (рубли/евро); доступ к курсу и игре lava.top присылает
  покупателю на email сам, бот только сообщает об оплате Лане. С лендинга
  курс открывается сразу по ссылке `?start=course`.
- **Аналитика воронки** — каждое нажатие кнопки пишется в таблицу `events`.

### Команды

Публичные:

- `/start` — приветствие и главное меню
- `/id` — узнать свой Telegram ID

Админские (только для ID из `ADMIN_IDS`):

- `/admin` — список админ-команд
- `/set_guide` — загрузить файл гайда (бот запомнит его и будет отдавать всем)
- `/broadcast` — рассылка всем пользователям: текст, фото, видео или голосовое
  (с превью и подтверждением)
- `/bookings` — ближайшие оплаченные/подтверждённые записи (список слотов)
- `/cancel` — отменить текущее действие

Плюс кнопки «✅ Подтвердить» / «❌ Отклонить» в уведомлении об оплате слота
(только для записей, оплаченных до переезда на lava.top: новые бот
подтверждает сам) и «✅ Подтвердить перенос» / «❌ Отклонить перенос» в уведомлении о запросе
на перенос записи менее чем за 24 часа до сессии.

## Стек

- Python 3.12, [aiogram 3.x](https://docs.aiogram.dev/)
- SQLAlchemy 2.0 (async) + asyncpg, PostgreSQL
- Google Calendar API (`google-api-python-client` + `google-auth`) — реальная
  занятость и создание событий записи
- Docker, хостинг на [Railway](https://railway.app/)

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
python main.py
```

### Переменные окружения

| Переменная              | Описание                                                                 |
| ------------------------ | ------------------------------------------------------------------------ |
| `BOT_TOKEN`              | Токен бота от [@BotFather](https://t.me/BotFather)                       |
| `ADMIN_IDS`              | Telegram ID админов через запятую (`111,222`). Узнать — `/id`            |
| `OWNER_CHAT_ID`          | Личка эксперта: всегда получает уведомления и права админа, независимо от `ADMIN_IDS`. Аккаунт должен нажать Start у бота |
| `DATABASE_URL`           | Строка подключения к PostgreSQL                                          |
| `TZ`                     | Часовой пояс, напр. `Europe/Prague`                                      |
| `LAVA_API_KEY`           | API-ключ lava.top (кабинет → Интеграции). Без него кнопки оплаты отвечают «оплата недоступна» |
| `GOOGLE_SA_CREDENTIALS`  | JSON-ключ сервис-аккаунта Google (путь к файлу или содержимое целиком)   |
| `CALENDAR_ID_BOOKINGS`   | Calendar ID календаря «Консультации» (куда бот пишет подтверждённые записи) |
| `CALENDAR_ID_PERSONAL`   | Calendar ID личного календаря Ланы (только для проверки занятости)       |
| `BOOKING_HOLD_MINUTES`   | Сколько минут слот держится за клиентом до оплаты (по умолчанию `30`)    |
| `BOOKING_HORIZON_DAYS`   | На сколько дней вперёд показывать слоты (по умолчанию `30`)              |
| `BOOKING_LEAD_HOURS`     | Минимальный отступ от «сейчас» до ближайшего доступного слота (по умолчанию `3`) |
| `WORK_TIMES`             | Время сессий через запятую, напр. `12:00,14:00,16:00`                    |
| `WORK_WEEKDAYS`          | Рабочие дни недели, `0`=пн … `6`=вс, напр. `0,1,2,3,4`                   |

Подробная пошаговая настройка Google-доступа (создание сервис-аккаунта,
расшаривание календарей, получение Calendar ID) —
[docs/google-calendar-setup.md](docs/google-calendar-setup.md).

## Деплой на Railway

1. Подключить репозиторий — Railway соберёт образ по `Dockerfile`.
2. Добавить PostgreSQL и прокинуть `DATABASE_URL=${{Postgres.DATABASE_URL}}`
   (бот сам приведёт `postgresql://` к `postgresql+asyncpg://`).
3. Задать `BOT_TOKEN`, `ADMIN_IDS`, `TZ` и все переменные Google Calendar
   из таблицы выше (см. [инструкцию по настройке](docs/google-calendar-setup.md)).
   Полноценных миграций нет, но `init_db` при старте **идемпотентно
   добавляет недостающие колонки** в уже существующие таблицы Postgres
   (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...`) — для чисто новых
   колонок (например, полей переноса записи) руками ничего делать не
   нужно, на свежей и на уже существующей базе всё поднимется само.
4. **Если на этой БД уже когда-либо запускался бот до ветки Google Calendar
   booking** — таблица `bookings` может быть в старой схеме
   (`slot_date`/`slot_time` вместо `slot_start`/`held_until`/
   `google_event_id`). Новый код с такой таблицей не заработает (упадёт на
   вставке/выборке). Один раз перед первым запуском новой версии выполни на
   этой БД: `DROP TABLE IF EXISTS bookings;` — данные там тестовые, бот ещё
   не запущен в проде, `create_all` пересоздаст таблицу в правильной схеме
   при следующем старте. Это нужно только при смене типа/состава колонок
   несовместимым образом (как тогда) — под добавление новых колонок ручной
   DROP больше не требуется, авто-миграция выше справляется сама.

После первого запуска:

- Каждый админ должен открыть бота и нажать `/start` — иначе бот не сможет
  присылать ему уведомления о заявках, бронях и оплатах.
- Загрузить файл гайда командой `/set_guide` — до этого кнопка «Забрать гайд»
  работает по резервной ссылке.
- Пройти [docs/google-calendar-setup.md](docs/google-calendar-setup.md) —
  без этого экран записи будет всегда показывать «Расписание сейчас
  недоступно».

## Известные ограничения

- **Статус оплаты бот опрашивает, а не получает вебхуком.** Бот работает
  на polling без публичного адреса, поэтому счёт lava.top проверяется
  каждые 20 секунд первый час, потом раз в 10 минут, через 48 часов
  опрос прекращается (кнопка «✓ Я оплатил(а)» проверяет и после). Обычно
  подтверждение приходит в пределах полуминуты после оплаты.
- **Цены живут в двух местах.** Сумму счёта задаёт оффер в кабинете
  lava.top, а тексты бота и сайта (`PRICE_TEXT`, `COURSE_PRICE_TEXT`,
  `GAME_PRICE_TEXT`) — витрина. Меняя цену в lava.top, поменяй и тексты:
  `test_prices_match_bot` сверяет сайт с ботом, но не с lava.top.
- **Гонка при одновременном бронировании одного слота** теоретически
  возможна (два клиента кликают один и тот же слот почти одновременно) —
  для объёма заявок этого бота риск признан приемлемым и отдельно не
  митигируется сверх проверки «слот всё ещё свободен» перед записью.
