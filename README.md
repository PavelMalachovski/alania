# alania

Telegram-бот воронки продаж для эксперта: прогрев аудитории, презентация услуг,
запись на консультацию по слотам, приём заявок, выдача бесплатного
гайда-лид-магнита, рассылки и дожим-напоминания.

## Возможности

- **Главное меню** — навигация по услугам и материалам (inline-кнопки).
- **Личная работа** — консультация «Точка сборки»: описание, «кому подойдёт»,
  как проходит сессия, отзывы с пагинацией.
- **Запись по слотам из Google Calendar** — бот сам считает свободное время
  (будни, `WORK_TIMES`) по занятости двух календарей Ланы (рабочего и
  личного), занятые и прошедшие слоты не показываются. Выбранный слот
  держится за клиентом `BOOKING_HOLD_MINUTES` (по умолчанию 30 минут), пока
  идёт оплата.
- **Оплата в два шага** — после оплаты по Tribute-ссылке (₽/€, `100 € /
  10000 ₽`) клиент жмёт «Я оплатил(а)» → в календаре «Консультации»
  создаётся событие → админам приходит уведомление с кнопками
  «✅ Подтвердить» / «❌ Отклонить» → Лана подтверждает (клиенту «Вы
  оплатили, спасибо…») или отклоняет (событие в календаре удаляется, слот
  освобождается).
- **Заявка** — пошаговая анкета (имя → запрос → контакт), сохраняется в БД,
  всем админам приходит уведомление с профилем клиента.
- **Дожим** — если человек интересовался консультацией, но за час не записался,
  бот один раз присылает «могу ли чем-то помочь?».
- **Гайд-лид-магнит** — «Карта твоего запроса» отдаётся файлом прямо из бота.
- **Рассылки** — любой контент: текст, фото, видео, голосовые.
- **Игра VECHNOST** и **бесплатный Telegram-канал** — ссылки-переходы.
- **Аналитика воронки** — каждое нажатие кнопки пишется в таблицу `events`.

### Команды

Публичные:

- `/start` — приветствие и главное меню
- `/id` — узнать свой Telegram ID

Админские (только для ID из `ADMIN_IDS`):

- `/admin` — список админ-команд
- `/set_guide` — загрузить файл гайда (бот запомнит его и будет отдавать всем)
- `/broadcast` — рассылка всем пользователям: текст, фото, видео или голосовое
  (с превью и подтверждением)
- `/bookings` — ближайшие оплаченные/подтверждённые записи (список слотов)
- `/cancel` — отменить текущее действие

Плюс кнопки «✅ Подтвердить» / «❌ Отклонить» в уведомлении об оплате слота.

## Стек

- Python 3.12, [aiogram 3.x](https://docs.aiogram.dev/)
- SQLAlchemy 2.0 (async) + asyncpg, PostgreSQL
- Google Calendar API (`google-api-python-client` + `google-auth`) — реальная
  занятость и создание событий записи
- Docker, хостинг на [Railway](https://railway.app/)

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
python main.py
```

### Переменные окружения

| Переменная              | Описание                                                                 |
| ------------------------ | ------------------------------------------------------------------------ |
| `BOT_TOKEN`              | Токен бота от [@BotFather](https://t.me/BotFather)                       |
| `ADMIN_IDS`              | Telegram ID админов через запятую (`111,222`). Узнать — `/id`            |
| `DATABASE_URL`           | Строка подключения к PostgreSQL                                          |
| `TZ`                     | Часовой пояс, напр. `Europe/Prague`                                      |
| `GOOGLE_SA_CREDENTIALS`  | JSON-ключ сервис-аккаунта Google (путь к файлу или содержимое целиком)   |
| `CALENDAR_ID_BOOKINGS`   | Calendar ID календаря «Консультации» (куда бот пишет подтверждённые записи) |
| `CALENDAR_ID_PERSONAL`   | Calendar ID личного календаря Ланы (только для проверки занятости)       |
| `BOOKING_HOLD_MINUTES`   | Сколько минут слот держится за клиентом до оплаты (по умолчанию `30`)    |
| `BOOKING_HORIZON_DAYS`   | На сколько дней вперёд показывать слоты (по умолчанию `30`)              |
| `BOOKING_LEAD_HOURS`     | Минимальный отступ от «сейчас» до ближайшего доступного слота (по умолчанию `3`) |
| `WORK_TIMES`             | Время сессий через запятую, напр. `12:00,14:00,16:00`                    |
| `WORK_WEEKDAYS`          | Рабочие дни недели, `0`=пн … `6`=вс, напр. `0,1,2,3,4`                   |

Подробная пошаговая настройка Google-доступа (создание сервис-аккаунта,
расшаривание календарей, получение Calendar ID) —
[docs/google-calendar-setup.md](docs/google-calendar-setup.md).

## Деплой на Railway

1. Подключить репозиторий — Railway соберёт образ по `Dockerfile`.
2. Добавить PostgreSQL и прокинуть `DATABASE_URL=${{Postgres.DATABASE_URL}}`
   (бот сам приведёт `postgresql://` к `postgresql+asyncpg://`).
3. Задать `BOT_TOKEN`, `ADMIN_IDS`, `TZ` и все переменные Google Calendar
   из таблицы выше (см. [инструкцию по настройке](docs/google-calendar-setup.md)).
   Миграций нет: `create_all` при старте только **создаёт отсутствующие**
   таблицы и никогда не меняет схему уже существующих — на свежей базе
   ничего дополнительно делать не нужно.
4. **Если на этой БД уже когда-либо запускался бот до ветки Google Calendar
   booking** — таблица `bookings` может быть в старой схеме
   (`slot_date`/`slot_time` вместо `slot_start`/`held_until`/
   `google_event_id`). Новый код с такой таблицей не заработает (упадёт на
   вставке/выборке). Один раз перед первым запуском новой версии выполни на
   этой БД: `DROP TABLE IF EXISTS bookings;` — данные там тестовые, бот ещё
   не запущен в проде, `create_all` пересоздаст таблицу в правильной схеме
   при следующем старте.

После первого запуска:

- Каждый админ должен открыть бота и нажать `/start` — иначе бот не сможет
  присылать ему уведомления о заявках, бронях и оплатах.
- Загрузить файл гайда командой `/set_guide` — до этого кнопка «Забрать гайд»
  работает по резервной ссылке.
- Пройти [docs/google-calendar-setup.md](docs/google-calendar-setup.md) —
  без этого экран записи будет всегда показывать «Расписание сейчас
  недоступно».

## Известные ограничения

- **Оплата подтверждается вручную.** Tribute не шлёт вебхуки — Лана
  проверяет поступление денег сама и жмёт «✅ Подтвердить» /
  «❌ Отклонить» в уведомлении. Автоматического списания статуса нет и не
  планируется без смены платёжной системы.
- **Гонка при одновременном бронировании одного слота** теоретически
  возможна (два клиента кликают один и тот же слот почти одновременно) —
  для объёма заявок этого бота риск признан приемлемым и отдельно не
  митигируется сверх проверки «слот всё ещё свободен» перед записью.
